[![CI](https://github.com/USERNAME/cats-vs-dogs-cv/actions/workflows/ci.yml/badge.svg)](https://github.com/USERNAME/cats-vs-dogs-cv/actions/workflows/ci.yml)

*[English version](README.md)*

Два эксперимента на одних и тех же двух классах, поставленные ради одного вопроса:
**насколько важно предобучение, когда датасет мал?**

Часть 1 сравнивает четыре классификатора на 2000 изображениях. Часть 2 — два
детектора на 401 размеченном вручную изображении. Каждая модель оценивается по
одной метрике на одной и той же выборке, отложенной и от обучения, и от подбора
гиперпараметров.

Короткий ответ: на датасете такого размера transfer learning — это не постепенное
улучшение по сравнению с обучением с нуля, а разница между рабочей и нерабочей
моделью.

## Результаты

### Часть 1 — классификация (тест, n = 300)

| Модель | Accuracy | Macro F1 | ROC-AUC | Avg. precision |
|---|---|---|---|---|
| **MobileNetV2 (transfer learning)** | **0.983** | **0.983** | **0.999** | **0.999** |
| HOG + LinearSVC | 0.607 | 0.607 | 0.646 | 0.626 |
| Небольшая CNN (с нуля) | 0.567 | 0.565 | 0.626 | 0.669 |
| Сырые пиксели + LogisticRegression | 0.490 | 0.489 | 0.506 | 0.497 |

Случайное угадывание на сбалансированной задаче даёт 0.50. Читая таблицу так,
три подхода из четырёх практически бесполезны: базовая модель на сырых пикселях
неотличима от подбрасывания монеты, а ни HOG, ни CNN с нуля не проходят рубеж
0.61. MobileNetV2 даёт 0.983 — разрыв в 0.376 macro F1 со следующей моделью, и это
от backbone, который на этом датасете вообще не обучался.

### Часть 2 — детекция

| Модель | Выборка | mAP50-95 | mAP50 | Precision | Recall |
|---|---|---|---|---|---|
| **YOLOv8n (с нуля)** | тест (n = 61) | **0.259** | **0.480** | 0.453 | 0.679 |
| YOLOv8n (с нуля) | валидация (n = 60) | 0.303 | 0.481 | 0.446 | 0.554 |
| D-FINE-n (с нуля) | валидация (n = 60) | 0.114 | 0.251 | — | 0.606 (AR100) |

D-FINE указан по валидации, потому что именно на ней он и был измерен: в исходном
запуске конфиг для оценки получался текстовой заменой из обучающего, замена молча
не срабатывала, и `--test-only` перечитывал валидационную выборку. В
`write_dfine_configs` это исправлено и покрыто тестом, но записанные числа
остаются теми, какие есть. Сравнивать их нужно с валидационной строкой YOLOv8n
(0.303 против 0.114), а не с тестовой.

Ни один детектор не загружал предобученные веса, так что здесь сравниваются
архитектуры при равном и жёстком дефиците данных. На валидации mAP50-95 у YOLOv8n
в 2.7 раза выше, mAP50 — в 1.9 раза. Трансформер не слабее в общем случае — он
слабее *здесь*, потому что set prediction в стиле DETR приходится учить
локализацию объектов, которую якорная сетка и свёрточные приоры YOLO дают
бесплатно. 280 обучающих изображений для этого категорически недостаточно.

Обе части говорят об одном: **индуктивное смещение заменяет данные.** Каждая цифра
в этих таблицах измеряет, сколько априорного знания модель принесла с собой.

## Что здесь есть

| Часть | Задача | Подходы |
|---|---|---|
| 1 | Бинарная классификация | Сырые пиксели, HOG, CNN с нуля, MobileNetV2 transfer learning |
| 2 | Детекция объектов | YOLOv8n и D-FINE-n, оба со случайной инициализации |

Помимо самих моделей:

- **Grad-CAM** для классификатора на transfer learning — проверка, смотрит ли
  модель с 98% на животное, а не на фоновую подсказку; реализовано и готово к
  запуску, почему ещё не запущено — см. [Выводы](#выводы)
- **Пайплайн ручной разметки** — Label Studio, экспорт в COCO, проверенная
  конвертация в формат YOLO
- **Таксономия ошибок** детекции: пропуски, дублирующие детекции и ошибки
  классификации считаются отдельно, потому что лечатся по-разному
- **Переиспользуемый пакет** (`src/cvlab/`) вместо кода, живущего только в
  ноутбуках, с тестами на те места, что ломаются молча

## Быстрый старт

```bash
git clone https://github.com/USERNAME/cats-vs-dogs-cv.git
cd cats-vs-dogs-cv

python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

pip install -e ".[classification]"     # часть 1
pip install -e ".[detection]"          # часть 2
pip install -e ".[dev]"                # тесты и линтер
```

Разложите данные согласно [`data/README.md`](data/README.md), затем:

```bash
# Часть 1 — обучить всё и получить сводную таблицу
python scripts/train_classifier.py --model all

# Или по одному подходу
python scripts/train_classifier.py --model hog
python scripts/train_classifier.py --model mobilenet

# Часть 2 — конвертировать COCO-экспорт, затем обучить
python scripts/prepare_detection.py
python scripts/train_detector.py --model yolov8

# Инференс на новых изображениях
python scripts/predict.py --task classify \
    --weights results/classification/weights/mobilenet.keras \
    --source data/new_images

python scripts/predict.py --task detect \
    --weights runs/yolo/yolov8n_scratch/weights/best.pt \
    --source data/new_images
```

Каждый запуск пишет метрики в `results/` в виде CSV, так что таблицы и графики
пересобираются без повторного обучения. Настройки лежат в `configs/*.yaml`, любую
можно переопределить из командной строки.

## Методика

### Оценка

**Основная метрика — macro F1, а не accuracy.** Accuracy на сбалансированном
датасете скрывает, на каком именно классе модель ошибается; macro F1 взвешивает
оба класса одинаково, поэтому модель не может выглядеть компетентной, просто
предпочитая более многочисленный класс.

Разбиение стратифицированное, 70/15/15. Валидационная выборка управляет выбором
модели и early stopping; **тестовая используется ровно один раз на модель**, в
конце. Grid search для HOG кросс-валидируется только на обучающей выборке, так что
подбор гиперпараметров тоже не видит отложенных данных. Разбиение происходит до
любого извлечения признаков и масштабирования, поэтому никакая статистика,
посчитанная на валидации или тесте, не может утечь в обучение.

Сиды зафиксированы на 42 для `random`, NumPy, TensorFlow и PyTorch. Разбиение для
детекции детерминированно выводится из COCO-экспорта, так что оба детектора видят
побайтово одинаковые данные.

### Часть 1 — четыре подхода по возрастанию априорного знания

Упорядочены по тому, сколько они уже знают об изображениях:

1. **Сырые пиксели + логистическая регрессия** — 64×64 в градациях серого,
   развёрнутые в 4096 признаков. Никакой пространственной структуры: линейная
   модель на таком входе никак не может знать, что два соседних пикселя связаны.
   Это честный нижний предел.
2. **HOG + линейный SVM** — сконструированные вручную гистограммы ориентаций
   градиента, `C` подобрана 3-фолдовым grid search (лучшее: `C = 0.1`, CV macro F1
   0.610). Настоящий приор о краях и форме, спроектированный человеком.
3. **Небольшая CNN с нуля** — три свёрточных блока, global average pooling вместо
   широкой dense-головы, dropout 0.3, легкая аугментация. Свёрточный приор теперь
   выучивается, а не проектируется.
4. **MobileNetV2 transfer learning** — замороженный ImageNet-backbone, затем
   fine-tuning со слоя 100 при `lr = 1e-5`. Два этапа важны: сначала обучается
   только голова, чтобы большие начальные градиенты не разрушили предобученные
   признаки, а низкий lr на fine-tuning сохраняет их, адаптируя.

Аугментация намеренно сдержанная — горизонтальный флип, поворот ±5%, зум ±10%. На
~1400 обучающих изображениях агрессивная аугментация стоит дороже, чем приносит, а
вертикальные флипы нереалистичны для фотографий животных.

### Часть 2 — два детектора, никаких предобученных весов

401 изображение, размеченное вручную: 465 рамок, 244 объекта «кошка» и 221
«собака», ~1.16 объекта на изображение. 30 рамок выходили за границы кадра и были
обрезаны, а не выброшены. Разбиение 280 / 60 / 61.

COCO JSON — единственный источник истины. Он проверяется один раз, разбивается один
раз, а затем выгружается в двух форматах: COCO для D-FINE и нормализованные
текстовые метки для Ultralytics. Конвертация рамок (`[x_min, y_min, w, h]` в
пикселях → `cx cy w h` нормализованные) проверяется чтением меток обратно с диска,
потому что ошибка здесь — классический молчаливый сбой в детекции: обучение идёт
идеально, а mAP около нуля.

**YOLOv8n** строится из `yolov8n.yaml`, а не `yolov8n.pt` — файл `.pt` подгрузил бы
веса COCO и обессмыслил сравнение. **D-FINE-n** использует backbone HGNetv2-B0 с
`pretrained: false`. По 80 эпох каждая, 640×640, порог уверенности 0.40. Инференс
D-FINE на новых изображениях шёл примерно на 34 FPS на T4.

## Выводы

**HOG почти не обошёл сырые пиксели на валидации.** 0.563 против 0.522 macro F1 —
прирост 0.041, что не тянет на решающее улучшение, которое обещает учебниковая
подача HOG. Разрыв отчётливо виден только на тесте (0.607 против 0.489). У кошек и
собак схожи силуэт, текстура шерсти и позы; HOG выбрасывает цвет — один из немногих
признаков, который их действительно различает. Дескриптор хорош ровно настолько,
насколько он подходит конкретной задаче.

**CNN с нуля проиграла HOG на тесте.** 0.565 против 0.607 macro F1. Больше ёмкости
без большего количества данных не даёт ничего: 1400 изображений не обеспечивают
градиентного сигнала, нужного свёрточному стеку, чтобы выучить полезные фильтры со
случайной инициализации. Модель подстроилась под обучающую выборку и обобщила хуже,
чем сконструированный вручную дескриптор с одним подобранным гиперпараметром.

**Пробить потолок удалось только предобучением.** То же семейство свёрточных
архитектур, что дало 0.565 с нуля, показало 0.983 с весами ImageNet. Архитектура не
менялась — изменилось то, что признаки были уже выучены, на миллионе изображений, к
которым этот проект доступа не имел.

**Grad-CAM реализован, но этот результат им не проверялся.**
`cvlab.classification.explain` находит целевой слой внутри вложенной подмодели
MobileNetV2 и строит тепловые карты, а исходный запуск дошёл только до
подтверждения слоя, к которому Grad-CAM подключится. Самих карт он не построил.
То есть 98% остаются непроверенными: модель может выдать такую точность на малом
датасете, эксплуатируя фотографическую закономерность вместо самого животного, и
метрика сама по себе не скажет, какой из двух случаев перед вами. Прогнать
`plot_gradcam_examples` по тестовой выборке — первое, чего этому проекту не хватает.

**Разрыв между recall и precision — самый явный сигнал в ошибках детекции.**
У YOLOv8n на тесте recall 0.679 против precision 0.453: модель находит объекты,
но её уверенность плохо калибрована, так что повышение порога отнимает recall,
которого и без того не хватает. Таксономия ошибок в `cvlab.detection.compare`
разделяет пропуски, дублирующие рамки и ошибки классификации — лечатся они
по-разному, — но в исходном запуске рассматривались только примеры каждого типа,
без подсчёта, поэтому утверждать, какой тип преобладает, здесь не будем.

**Трансформерный детектор отстал, что ожидаемо в этих условиях.** D-FINE дал
mAP50-95 0.114 на валидации против 0.303 у YOLOv8n на той же выборке и mAP75 всего
0.076 — он локализует рыхло.
При этом AR100 0.606 показывает, что объекты он находит; он просто не может
поставить на них плотные рамки. Архитектуры в стиле DETR обменивают
сконструированные приоры на выучиваемое set prediction, и это хорошая сделка на
данных масштаба COCO и плохая — на 280 изображениях.

### Честные ограничения

- **2000 изображений для классификации и 401 для детекции** — это мало. Разница в
  несколько пунктов здесь ненадёжна; те разрывы, на которых держится вывод (0.376
  macro F1, двукратный mAP), достаточно велики, чтобы это выдержать.
- **Один запуск на модель, без доверительных интервалов.** Сиды зафиксированы для
  воспроизводимости, а не для оценки разброса.
- **Один разметчик на изображение, без оценки согласованности разметки.** Плотность
  рамок — реальный источник шума в числах mAP50-95.
- **Результат MobileNetV2 — не общее утверждение про кошек и собак.** В ImageNet
  много пород кошек и собак, поэтому эта задача переноса необычно благоприятна. На
  классах, которых в ImageNet нет, будет сложнее.
- **В этих двух экспериментах нет OpenCV.** Стек — Pillow, scikit-image,
  scikit-learn, Keras, Ultralytics и PyTorch. Указано здесь, чтобы список
  зависимостей не приняли за то, чем он не является.

## Структура проекта

```
├── src/cvlab/                  # пакет — вся логика здесь
│   ├── common/                 # конфиги, сиды, IO, графики
│   ├── classification/         # часть 1: данные, признаки, модели, оценка, Grad-CAM
│   └── detection/              # часть 2: COCO, конвертация, YOLO, D-FINE, сравнение
├── scripts/                    # точки входа CLI
│   ├── train_classifier.py
│   ├── prepare_detection.py
│   ├── train_detector.py
│   └── predict.py
├── notebooks/                  # разборы с повествованием, импортируют из src/
├── configs/                    # classification.yaml, detection.yaml
├── tests/                      # набор pytest, не требует GPU и тяжёлых фреймворков
├── docs/                       # methodology.md, results.md
└── data/                       # не коммитится — см. data/README.md
```

Ноутбуки импортируют из `src/cvlab`, а не переопределяют логику, так что
исправление попадает в одно место, а повествование в ноутбуке остаётся читаемым.

## Разработка

```bash
pip install -e ".[dev]"

pytest -q                                   # 70 тестов
ruff check src scripts tests
ruff format src scripts tests
python tests/check_notebooks_clean.py       # падает, если в ноутбуках остались выводы
```

Набор тестов намеренно обходится без TensorFlow и PyTorch. Он покрывает геометрию
рамок, проверку COCO, разбиение датасета, таксономию ошибок и валидацию конфигов —
код, где баг выдаёт правдоподобно выглядящие неверные числа вместо исключения. CI
запускает те же команды на Python 3.11.

Перед коммитом ноутбуков установите
[nbstripout](https://github.com/kynan/nbstripout):

```bash
pip install nbstripout && nbstripout --install
```

## Воспроизведение экспериментов с детекцией

У D-FINE нет Python API — это исследовательский репозиторий, управляемый
YAML-конфигами и CLI-тренером. `scripts/train_detector.py --model dfine` генерирует
конфиги и вызывает его, поэтому сначала склонируйте:

```bash
git clone https://github.com/Peterande/D-FINE third_party/D-FINE
pip install -r third_party/D-FINE/requirements.txt
```

Общее время обучения — около 1.5 GPU-часа на T4 на оба детектора.
